## Problem Statement
Build a fast, impressive demo of a personal email assistant for busy founders/operators: triage a chaotic 50+ email Monday inbox into clear priorities in 60 seconds.

## What Makes This Cool
The "whoa" moment is seeing inbox chaos collapse into an actionable 3-lane board (`Do Now`, `Track`, `Ignore`) with extracted deadlines and follow-ups, powered by a modern local agentic stack.

## Constraints
- Demo-first, high reliability in a live presentation
- Must showcase personal ML/AI capability, not just UI polish
- Use local model serving with Ollama hosting Qwen3
- App server must be FastAPI + Uvicorn
- UI client must be Chainlit using httpx calls to the app server
- Prefer seeded realistic dataset over live IMAP risk
- Show detailed, legible agent execution trace during demo (steps, reasoning outputs, scores)
- Use explicit functional multi-agent roles for storytelling
- Unsubscribe must be functionally wired (not simulated)
- Demo balance target: ~70% technical depth / ~30% storytelling polish

## Premises
1. Demo impact is more important than production integration depth.
2. A seeded dataset is acceptable if runtime AI inference is real.
3. The architecture should make your stack choices visible and defensible.
4. Scope should stay on one polished end-to-end triage flow.

## Approaches Considered
### Approach A: Demo-First Triage Board
Single interactive UI with pre-seeded results.
- Pros: Fastest, lowest risk
- Cons: Weaker technical credibility

### Approach B: Hybrid “Looks Live” Pipeline (Chosen)
Seeded inbox data, runtime AI triage/summarization through local model service, then live UI update.
- Pros: Strong demo reliability + real AI behavior, reusable foundation
- Cons: More integration effort than a pure mock

### Approach C: Narrated Simulation
Highly polished scripted animation and narration.
- Pros: Quick to build, visually strong
- Cons: Low technical depth signal

## Recommended Approach
Use Approach B and design the demo around three visible layers:
1. **Model Server**: Ollama with Qwen3 for categorization + short summaries
2. **Application Server**: FastAPI/Uvicorn orchestration API for ingest, classify, summarize, and board aggregation
3. **UI Client**: Chainlit front-end calling FastAPI via httpx for trigger + render loop

Add an explicit multi-agent orchestration layer in the app server so the demo can narrate agent collaboration, not just show a monolithic classifier.

## Demo Flow (Target: 60-90s live)
1. Load "Monday Chaos Inbox" dataset (50+ mixed emails).
2. Trigger `Triage Inbox` action in Chainlit.
3. Show per-batch progress state with agent-level trace:
   - ingest -> classify -> summarize -> prioritize -> action extraction -> board
   - live scores and confidence per email/batch
4. Reveal final triage board:
   - `Do Now`: urgent actions and deadlines
   - `Track`: ongoing shipments/events/trips
   - `Ignore`: low-signal promotions/newsletters
5. Perform one quick action (archive/snooze/pin) and one real unsubscribe action to prove interactivity.

## Technical Shape
- **Ollama/Qwen3**: local inference endpoint for structured triage output
- **Functional multi-agent roles (explicit):**
  - **Classifier Agent**: assigns base category + confidence
  - **Summarizer Agent**: produces 1-2 sentence summary and key entities
  - **Priority Agent**: maps items into `Do Now` / `Track` / `Ignore` with score
  - **Action Agent**: extracts actionable next step + deadline, identifies unsubscribe candidates
- **FastAPI endpoints**:
  - `POST /triage/run`
  - `GET /triage/status/{run_id}`
  - `GET /triage/result/{run_id}`
  - `POST /actions/unsubscribe`
- **Chainlit client**:
  - starts run
  - polls status with httpx
  - renders board + item details + quick actions
  - renders "Agent Trace" panel with per-step output and scores
- **Data**: deterministic seeded JSON mailbox fixture for repeatable demos

### Agent Trace Output Contract (for storytelling)
Each processed message should produce a compact trace record:
- `message_id`
- `agent_steps[]` with `agent_name`, `input_ref`, `output`, `confidence`, `latency_ms`
- `priority_score` (0-100)
- `score_rationale` (short explanation for why the score was assigned)
- `final_lane` (`Do Now` | `Track` | `Ignore`)
- `unsubscribe_recommended` (boolean)

Expose trace in `GET /triage/result/{run_id}` so Chainlit can stream or render a detailed execution log.

## Open Questions

3. Resolved: unsubscribe uses generic `List-Unsubscribe` header execution (`mailto`/URL flow) for demo scope.

## Success Criteria
- Live demo completes in under 90 seconds, target 60
- Audience can explain the three lanes immediately
- At least 3 extracted deadlines/follow-ups are clearly correct
- Stack visibility is explicit: Ollama/Qwen3, FastAPI/Uvicorn, Chainlit/httpx
- Audience can follow multi-agent flow from trace output without narration help
- Every triaged item shows confidence and priority score plus rationale
- Agent Trace is readable in collapsed-card default layout during live demo
- Unsubscribe action executes functionally through generic `List-Unsubscribe` header handling and updates board state live
